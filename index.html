page 02 / 08 — the gap

The gap

one category, one empty column

Roughly half of organizations already experiment with MCP; only ~11% run it in production. Thousands of MCP servers are publicly reachable — several hundred have leaked credentials. A funded security category grew out of this: all of it on the consumer side.

The operator who publishes the server — the one actually holding the database — has nothing. That empty column is this product.

Cerca de la mitad de las organizaciones ya experimenta con MCP; solo ~11% llega a producción. Miles de servidores MCP son alcanzables públicamente — varios cientos han filtrado credenciales. De ahí creció una categoría de seguridad financiada: toda del lado consumidor.

El operador que publica el servidor — el que realmente sostiene la base de datos — no tiene nada. Esa columna vacía es este producto.

page 03 / 08 — eight layers

What it does

solid underline = shipped · dashed = design hook — honesty policy
  1. Agent identity — x-agent-name / passport header, optional /.well-known/agent.json verification, --require-identity refuses anonymous calls.shipped
  2. Reputation — per-agent score built from identity verdicts and behavior.hook
  3. Threat intel in/out — IOC matching on domains, URLs, IPs, emails, hashes, wildcards, mutexes. Applied to inbound args and outbound responses.shipped
  4. Rate limits — token bucket per agent+tool, free/paid tiers. Abuse gets 429 before it gets your database.shipped
  5. Billing — per-call metering + x402-ready pricing manifest at GET /pricing; settlement plugs into your payment layer.metering
  6. DLP — emails, JWTs, AWS keys, API tokens, private keys, cards masked in responses. Your API can't leak what it never emits.shipped
  7. Reverse drift — notify clients when your schema changes. Fewer broken agents, more trust.hook
  8. Audit — JSONL per decision. Indicator + campaign recorded for triage, never raw arguments. SIEM-grade hygiene.shipped

~1,300 auditable lines of Node ≥18 (ESM), hand-rolled MCP stdio (newline-delimited JSON-RPC 2.0, protocol 2025-06-18). A security product with 47 transitive dependencies is an attack surface, not a defense.

page 04 / 08 — use case

Day one on a CRM server

the same data class Apollo.io exposes via mcp.apollo.io

You publish an MCP server that exposes contacts, pipelines and email history. Today any anonymous agent can hammer it, exfiltrate PII through it, or use it as a lookup oracle. You wrap it once:

npx uta-shield wrap --upstream http://localhost:3001 --port 8787

From then on agents talk to :8787. Four things happen on day one — the four verdicts below.

Publicas un servidor MCP que expone contactos, pipelines e historial de email. Hoy cualquier agente anónimo puede golpearlo, extraer PII a través de él, o usarlo como oráculo de consulta. Lo envuelves una vez:

npx uta-shield wrap --upstream http://localhost:3001 --port 8787

Desde ahí los agentes hablan con :8787. El día uno pasan cuatro cosas — los cuatro veredictos de abajo.

verdict 01
ALLOW
A legitimate client calls search_contacts. Call passes, 23 ms, metered to the ledger.
identity=copilot-cli · tier=free → ledger.jsonl
verdict 02
DLP
The response contains the fetched record. Two emails masked, one AWS key blocked — the wall emits it clean.
2 masked · 1 blocked → response leaves clean
verdict 03
BLOCK_INTEL
An argument references gaganata.ink — a live C2 from the bundled feed. Blocked, with evidence attached so the agent can reason about WHY.
domain=gaganata.ink · role=C2 · campaign=taikotalent-2026-10
verdict 04
429
Same agent retries forty times a minute. The bucket empties; your upstream never sees it.
rate_limit · agent=anonymous · tool=search_contacts

Every decision leaves a line — operator telemetry only. No admin token configured → /audit answers 404 (fail-closed); wrong token → 401, and the denial is audited. Triage reads verdicts and campaigns — never your users' raw arguments.
