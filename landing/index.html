01 — The gap

Half the industry is experimenting with MCP. Almost nobody is protecting the server side.

Roughly half of organizations are already experimenting with MCP, yet only ~11% run it in production. Meanwhile thousands of MCP servers are publicly reachable — and several hundred have leaked credentials. The whole security category (Lasso, Mintive, Obot, Solo.io agentgateway, Cequence) grew on the consumer side: enterprises filtering what their agents may call. The operator who PUBLISHES a server has… nothing. UTA Shield exists to fill exactly that empty column.

Cerca de la mitad de las organizaciones ya experimenta con MCP, pero solo ~11% lo lleva a producción. Mientras tanto, miles de servidores MCP son alcanzables públicamente — y varios cientos han filtrado credenciales. Toda la categoría de seguridad (Lasso, Mintive, Obot, Solo.io agentgateway, Cequence) creció del lado consumidor: empresas filtrando qué pueden llamar sus agentes. El operador que PUBLICA un servidor tiene… nada. UTA Shield existe para llenar exactamente esa columna vacía.

03 — Use case

You run a CRM-style MCP server. Here is your day one.

Your company publishes an MCP server that exposes contacts, pipelines and email history — the same data class Apollo.io exposes via mcp.apollo.io. Today any anonymous agent can hammer it, exfiltrate PII through it, or use it as a lookup oracle. With UTA Shield you wrap it once and the firewall answers all of it: who is calling (identity), what they may see (DLP), how fast they may call (rate limit), and whether they are known-bad (threat intel) — while the metering endpoint turns your API into a billable, x402-ready product.

Tu empresa publica un servidor MCP que expone contactos, pipelines e historial de email — la misma clase de datos que Apollo.io expone vía mcp.apollo.io. Hoy cualquier agente anónimo puede golpearlo, extraer PII a través de él, o usarlo como oráculo de consulta. Con UTA Shield lo envuelves una vez y el firewall responde todo: quién llama (identidad), qué puede ver (DLP), a qué velocidad puede llamar (rate limit) y si es conocido-malo (threat intel) — mientras el endpoint de metering convierte tu API en un producto facturable, listo para x402.
